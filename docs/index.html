01为什么单独成一个仓库

被驱动的东西不该和被驱动的接口焊在一起。

这两样原先住在编辑器仓库内部：MCP 是 server.js 的一个路由， 靠注入进程内函数（readWorld / writeWorld / listWorlds）干活；Skill 则躺在编辑器的 .qoder/skills/ 下。 结果是：想把接入层给别人用，得先把整个编辑器——含官方素材、地图存档、Three.js——一起给出去。

拆开之后依赖方向变成单向的：本仓库依赖编辑器的 HTTP 接口，编辑器不知道本仓库存在。 所以编辑器换版本、换目录，甚至换成官方桌面版，这一层都不用改。

mcp/ ArenaPro 兼容 MCP 服务

独立进程的 SSE 服务，纯 HTTP 代理：不 import 编辑器模块，也不读它的文件。给 IDE 里的 Agent 用。

skill/dao3-editor/ Qoder Skill + CLI

零依赖命令行，建图 / 批量写体素 / 读写两端脚本 / 存盘 / 查规范。给终端里干活的人和 Agent 用。

02装 Skill

默认软链：改这份仓库，所有装了它的工程立刻跟着变。这类「给 AI 的规范」最容易出的事故就是各处副本各自漂移。

$ ./install.sh /path/to/your/project    # 软链进该工程的 .qoder/skills/
$ ./install.sh --copy                   # 要落盘副本时用（跨机器同步、要提交进那个工程）
$ node skill/dao3-editor/scripts/dao3.mjs health   # 验证

CLI 长什么样

dao3.mjs blocks --grep 草                              # 写体素前先查方块 id，别猜
dao3.mjs scaffold demo --shape 64,64,64 --floor 0     # 建一张 64³ 的空图
dao3.mjs fill demo --box 4,1,4,12,6,12 --id 30        # 一个长方体平台
dao3.mjs probe demo --at 8,8                          # 回读，确认真的落下去了
dao3.mjs api say                                      # 查官方 API 签名与中文说明

每条写操作后面都跟一条 probe。写体素是全量覆盖、没有补丁接口， 所以「我以为写进去了」和「它真的在里面」是两件事。

03工具矩阵：官方 24 个名字全部在册

端口 25315、路径 /ap-mcp 就是官方 ArenaPro 插件用的那一套。 机器可读版本：curl -s http://127.0.0.1:25315/api/mcp/tools

状态工具名说明
可用 11 file_mapTool file_createProject map_showMap map_playData map_resource file_upLoad file_buildNUpload file_checkDts chatjpt_onlyKnowledgeBase component_showComponentStats file_outputName 建图、读写地图与脚本、资产上传、规范检索、组件统计
不支持 13 userCenterTool_* ×4、file_npm_package_*、file_reHMR、 file_stopHMR、file_openArena、file_debugger、 file_openOutputLog、file_dao3config_open、file_nodeJs_setting 调用得到 isError + 明确原因，而不是 unknown tool

两个值得说明的决定

账号类工具绝不假装成功

这里没有账号体系，userCenterTool_* 返回 isError 并写清原因， 不会吐出一个假 token。一个会返回假凭据的登录工具，比没有这个工具危险得多。 回归里专门有一条：拒绝文本中不得出现像 JWT 的串。

做不到的仍然留在 tools/list 里

客户端按官方清单调用时若拿到 unknown tool，Agent 会认为契约对不上而开始猜接口。 给一个明确的「不支持 + 为什么」更好。
顺带：file_reHMR / file_stopHMR 不支持其实是好消息—— 编辑器没有构建步骤，改完刷新即可。

04官方 API 全量规范随 skill 一起给

AI 最容易犯的错不是语法，是编一个看起来合理的接口名。所以带了三份，而且规定：查不到就明说没有。

文件内容为什么这么切
references/api.md100 个类的索引 + 端归属 + 成员数目录，不整篇读
references/scripting.md两端全局划分、单位制、四元数序、颜色量纲写之前必读的硬规范
dao3.mjs api1044 个成员按名字精确检索签名与官方中文说明按需查，不进上下文

完整文档有 1.7 万词，不该整篇进上下文——那是「目录 + 按需查」的分工。

规范数据从编辑器的 /data/api-spec.json 取，和文档站、应用内 AI 的规范注入同源， 所以「AI 以为有的接口」和「实际实现的接口」不会各说一套。

三条会咬人的规范

  • 单位是「格 / tick」，TICK_MS=64 → 15.625 tick/秒（不是 20 TPS）。 walkSpeed 0.22 ≈ 3.4 格/秒。当成格/秒，人物慢 15 倍。
  • 四元数是 xyzw。 实测官方 432 个实体朝向：276 个 [0,0,0,1]、0 个 [1,0,0,0]。
  • 两端全局不是一套。 服务端独占 storage voxels resources 与全部 Game*；客户端独占 ui input screen 与全部 Ui*。写错端不会立刻报错，是 undefined。

05边界

不联网

只做本地 HTTP。规范检索是查本地数据文件，不调模型。

没有账号系统

官方登录 / Token / 线上游玩统计拿不到，也不伪造。

写体素是全量覆盖

编辑器没有补丁接口。两个进程同时改同一张图会互相覆盖。

自动存档会打架

浏览器开着那张图时，编辑器的自动存档可能盖掉 CLI 的改动。先关标签页，或改完 probe 复查。

项目包 .zip 导出在编辑器浏览器侧（依赖 Three.js），CLI 里没有等价命令。

06验证

$ node test/site.mjs
site: 14 passed, 0 failed        # 纯离线
$ NET=1 node test/site.mjs
site: 20 passed, 0 failed        # 再联网查介绍页每个外链是否还活着
$ node test/mcp.test.mjs
mcp-arenapro: 26 passed, 0 failed  # 需要编辑器在跑

site.mjs 存在的原因是本页与 README 里有写死的数字（11 / 13 / 24）。 这类数字漂移过一次教训：加一个工具、忘了改文档，文档就开始说谎。 所以它直接 import mcp/tools.mjs 拿真实键数来对，而不是再抄一遍常量。

MCP 那 26 条里自己实现了一个最小 MCP 客户端：开 SSE、按 JSON-RPC 走 initialize → tools/list → tools/call。它不 import 被测模块—— 自己测自己等于自己给自己打分。

覆盖：官方 24 个工具名全部在册、账号工具返回 isError 且不含 JWT 样串、 真建一张图再写脚本再删掉、checkDts 不被注释里的假引用骗到、 路径穿越被明确拒绝而不是清洗后照写还报成功。

这条踩过一次：MCP 的 endpoint 帧按规格是纯文本 URL，实现时多包了一层 JSON 引号， 结果任何真实 MCP 客户端都连不上，而本地测试全绿——因为测试客户端跟着一起错。 自测自洽证明不了兼容。
